# Пакетний друк PDF

Утиліта для Windows, яка друкує велику кількість окремих PDF **пачками з паузою між ними**, щоб принтер не захлинався.

Навіщо: якщо відправити на друк одразу сотні файлів або один великий об'єднаний PDF, офісний принтер переповнює пам'ять — друк заїдає, вилітають пусті сторінки. Утиліта подає файли порціями (наприклад, по 50), чекає, поки принтер **справді** закінчить друк, робить паузу (наприклад, 5 хв) і продовжує.

## Можливості

- Папка з PDF → друк → файл автоматично переноситься в папку «надруковані» (зрив у будь-який момент — продовжуєте з того ж місця, нічого не друкується двічі).
- Розмір пачки, пауза між пачками, загальний ліміт (або вся папка).
- Двосторонній друк (довгий / короткий край), кольоровий або чорно-білий, якість 150–600 DPI.
- Кожен PDF — окреме завдання: при двосторонньому друці кожен документ починається з нового аркуша.
- Кінець друку визначається не лише за чергою Windows, а й за станом самого принтера по мережі (SNMP: стан «готовий» і лічильник сторінок перестав рости). Помилку принтера (застрягання, нема паперу) утиліта бачить і чекає, поки її усунуть. Якщо принтер не відповідає по SNMP — чекає заданий час.
- Не завалює чергу Windows: тримає в ній не більше N завдань одночасно.
- Файли з помилкою — в підпапку `_помилки`, журнал — `журнал друку.txt` у папці надрукованих.
- Пауза / Стоп (поточний файл допрацює), налаштування запам'ятовуються.
- Принтер «Microsoft Print to PDF» пише результат у `_тест_pdf` — зручно перевірити без паперу.

## Запуск

Завантажте `BatchPrint.exe` з розділу [Releases](../../releases) і запустіть — встановлення не потрібне. Потрібна Windows 10 або 11 (PDF рендериться вбудованим рушієм Windows, .NET Framework 4 уже є в системі).

## Збірка

SDK не потрібен — лише компілятор .NET Framework і метадані Windows SDK (`UnionMetadata\...\Windows.winmd`):

```
build.cmd
```

Налаштування зберігаються в `%APPDATA%\BatchPrint\settings.ini`.
